## 4. 推荐系统最小知识闭环

### 4.1 全链路

以“1000 万个可推荐视频/直播间，给用户返回 20 个”为例：

1. Retrieval：从 1000 万降到约 1 万。可并行使用 popularity、follow/social、ItemCF、two-tower ANN、content/semantic、exploration 等通道。
2. Pre-ranking：从 1 万降到约 1000。使用较轻模型和少量实时特征。
3. Ranking：从 1000 降到约 100。预测 watch、click、follow、order 等多目标。
4. Reranking：输出 20 个。处理 diversity、freshness、作者去重、内容安全、商品/预算约束和探索配额。

面试关键：每一层都要说目标、输入、输出规模、模型、latency budget 和评估指标。

### 4.2 Two-tower / YouTubeDNN

- user tower 编码 user profile、context、history；
- item tower 编码 item ID/content/creator；
- dot product 或 cosine 作为相似度；
- 训练可用 sampled softmax、in-batch negatives、InfoNCE；
- serving 时预计算 item embedding，用 ANN 检索。

优点：适合大规模 retrieval，item embedding 可预计算。缺点：user/item 在打分前没有充分 cross interaction，复杂匹配能力弱。

高频追问：

- false negative 怎么办；
- popular item 被采样更多造成什么偏差；
- temperature 的作用；
- 为什么 in-batch negative 高效；
- 新 item 如何用 content tower 冷启动；
- ANN 为什么不是精确 Top-K，HNSW/IVF/PQ 的取舍。

### 4.3 Ranking models

只需要达到下面深度：

- Wide&Deep：wide 记忆显式交叉，deep 学泛化。
- FM/DeepFM：FM 二阶 embedding interaction；DeepFM 共用 embedding 做 FM + DNN。
- DCN：显式学习 bounded-degree feature crosses。
- DIN：target-aware attention，从历史行为中提取与当前 candidate 相关的兴趣。
- SASRec：causal self-attention 编码行为序列做 next-item prediction。

不要花时间背大量模型年份；重点能解释输入、交互方式、loss、计算复杂度和适用阶段。

### 4.4 Multi-task

直播电商可能同时预测：

- valid watch、watch30、watch200；
- follow、like/comment/share；
- product click；
- order/payment；
- GMV/value。

常用方法：

- shared-bottom：简单但可能 negative transfer；
- MMoE：多个 expert，经 task-specific gate 组合；
- PLE：区分 shared expert 与 task-specific expert，逐层分离；
- loss weighting：固定权重、uncertainty weighting、GradNorm、DWA。

面试时不要只说“加权求和”。先说 label frequency、gradient scale、task conflict，再决定权重。

### 4.5 CTR/CVR/ESMM

- CTR = P(click | impression)
- CVR 通常指 P(conversion | click)
- CTCVR = P(click and conversion | impression)
- 在常见定义下：CTCVR = CTR × CVR

只在 clicked samples 上训练 CVR 会有 sample selection bias，且 conversion 稀疏。ESMM 在 entire impression space 上联合学习 CTR 与 CTCVR，并由两者关系得到 CVR。

直播电商额外要处理：

- delayed conversion：曝光或点击后很久才下单；
- attribution window：例如 1 小时、24 小时、7 天会产生不同 label；
- refund/cancel；
- 商品库存和价格变化；
- 同一直播间中主播和商品贡献难分。

### 4.6 Metrics

- LogLoss：概率 calibration 和逐样本误差。
- AUC：随机取一个 positive 和一个 negative，模型把 positive 排在前面的概率。
- GAUC：按 user/request group 算 AUC 后加权，更贴近个性化排序。
- HitRate@K：ground-truth item 是否进入 Top-K。
- Recall@K：多个 relevant items 中召回比例。
- NDCG@K：考虑 Top-K 位置 discount 和 graded relevance。
- Online：watch time、retention、order、GMV、complaint/negative feedback、latency。

必须会回答：AUC 只关心相对次序，不保证 calibration；global AUC 还可能被不同 user 的分数尺度污染。

### 4.7 Offline-online mismatch

排查顺序：

1. 数据/特征一致性：training-serving skew、timestamp、feature freshness。
2. label：attribution window、delayed feedback、leakage。
3. 样本：negative sampling 和线上曝光分布不同。
4. metric：AUC 与 Top-K/GMV 目标不一致。
5. calibration：排序变好但 score scale 改变，影响 fusion。
6. system：retrieval bottleneck 使 ranking gain 无法触达。
7. interaction：策略改变用户行为和后续数据分布。
8. AB：分流污染、样本量、novelty effect、网络/双边市场 interference。

## 5. Generative Recommendation 速成

### 5.1 基本定义

传统系统为每个 candidate 独立预测 score；Generative Recommendation 把 item 表示成 token sequence，并学习：

P(item | user context) = ∏ P(SID level l | user context, previous SID levels)

例如某商品不是一个 5000 万类的 raw ID，而是三层 SID：

- level 1：electronics
- level 2：mobile phone
- level 3：specific item cluster/leaf

真实 SID 不一定可人工解释，但通常 coarse-to-fine。

### 5.2 为什么需要 Semantic ID

直接把每个 item 当一个 vocabulary token：

- vocabulary 太大；
- 新 item 需要扩词表；
- item 间没有共享结构；
- long-tail item 监督太少。

Semantic ID 用 RQ-VAE/RQ-Kmeans 等把 dense item embedding 分层量化成短 token sequence：

- shared prefix 可表达相似语义/协同关系；
- vocabulary 小很多；
- 自回归模型可 coarse-to-fine 搜索；
- 可结合 content 处理 cold start。

### 5.3 Semantic ID 必问缺点

1. Collision：多个 item 有相同 code，需要 disambiguation token 或 leaf mapping。
2. Codebook collapse：少数 code 被过度使用，出现 dead codes。
3. Stability：item embedding/codebook 更新会导致 SID drift。
4. Semantics vs collaboration：纯 content semantic 不等于用户协同偏好。
5. Dynamic inventory：商品、广告、直播间快速变化。
6. Invalid generation：生成的 token path 不对应合法 item。

解决思路：balanced quantization、collaborative + multimodal joint embedding、versioned codebook、trie constraints、dynamic SID、fallback retrieval。

### 5.4 为什么能统一 retrieval 与 ranking

传统 retrieval 优化 coverage/recall，ranking 优化 CTR/CVR/value，stage objective 不一致。Generator 可直接在一个 conditional sequence model 中生成 candidate，并在 post-training 中对齐最终 reward。

但面试必须补一句：工程上“一模型完全替代 cascade”不是自动成立。必须解决：

- decoding latency；
- dynamic constraints；
- candidate coverage；
- online reliability；
- value calibration；
- rollback 和 fallback；
- 训练数据仍来自旧 policy 的 exposure bias。

### 5.5 Constrained decoding

使用 trie 保存当前合法 SID path：

- 每一步只允许扩展合法 child token；
- 可提前过滤下架商品、库存、地域、年龄、预算等约束；
- beam score 可融合 generation probability 与 value model；
- 避免生成不存在的 item 和事后大规模过滤。

### 5.6 GPR 三阶段

1. Pre-training：MTP 学多兴趣与行为序列。
2. Value-Aware Fine-Tuning：按 action type 和 eCPM/value 重加权。
3. HEPO post-training：在 simulator 中探索未被历史 policy 充分曝光的高价值候选，做 hierarchical credit assignment。

面试官可能追问：为什么历史 supervised logs 不够？答：只覆盖旧 policy 的 action support，模型容易 imitation old policy，无法评估未曝光候选的 counterfactual value。

### 5.7 V-STAR 与你的 GRPO 经验

标准 beam search 以 likelihood 剪枝，但 recommendation 想最大化 reward。两者可能不一致：

- low-probability prefix 下面可能有 high-GMV long-tail item，却被早早剪掉；
- beam candidate 共享高概率 prefix，reward 高度相关，GRPO 的 group advantage 区分度低。

V-STAR：

- VED：用 value + uncertainty 找 decisive prefix，只在那里增加 search budget；
- Sibling-GRPO：按同一 parent 的 sibling 做 relative advantage，把学习信号放在真正分叉的 token 上；
- training 时做较重 exploration，online inference 仍可使用低延迟 decoder。

这是你最该主动提到的论文，因为它直接连接 Semantic ID、GRPO、exploration、GMV。

### 5.8 SSRLive

直播间与普通短视频不同：

- streamer 的长期属性相对稳定；
- 当前讲解商品、实时热度、互动节奏快速变化；
- user-streamer 历史关系很重要；
- watch、follow、interaction、order 是不同 task。

SSRLive 用 static SID 表示历史多模态 streamer 内容，用 dynamic SID 表示实时 live-room state；generative module 学 SID，discriminative module 融合 user-live cross feature 做 multi-task prediction。

高质量回答要指出：纯 Generative Recommendation 未必足够，直播场景保留 discriminative cross interaction 很合理。

## 6. “设计视频号直播电商推荐系统”标准答题框架

### 6.1 先澄清目标

“我先确认推荐对象是直播间还是直播间内商品；以下假设是给用户推荐直播间，进入后再做商品排序。目标不是只最大化 GMV，而是在用户体验、商家/主播生态与平台交易之间做约束下优化。”

### 6.2 Labels

- engagement：enter、valid watch、watch time、follow、like/comment/share；
- commerce：product click、add-to-cart、order、payment、GMV、refund；
- negative：quick skip、not interested、complaint；
- long-term：next-day/7-day retention、repeat purchase。

### 6.3 Features

- user：long-term profile、short-term session、multi-scene history、social/follow graph；
- streamer：category、quality、history performance、creator embedding；
- live room：current transcript、frames/audio、current product、real-time popularity/interaction；
- product：category、price、stock、brand、conversion history、multimodal content；
- context：time、network、device、entry source。

所有统计特征必须按 event time 构造，防止 leakage。

### 6.4 Cascade baseline

1. Retrieval：social/follow、popular/live-now、two-tower ANN、content semantic、collaborative、exploration。
2. Pre-ranking：轻量模型预测 valid watch/order。
3. Ranking：DIN/SASRec + MMoE/PLE，多任务预测 watch/follow/order。
4. Fusion：用 calibrated scores 和业务约束组合，不直接盲加未经 calibration 的概率。
5. Reranking：diversity、freshness、主播去重、库存、安全、探索、新主播扶持。

### 6.5 Generative version

1. 对 streamer/product 的 multimodal + collaborative representation 做 hierarchical SID。
2. live room 使用 static SID + real-time dynamic SID。
3. Transformer/HSTU 编码 user long/short sequence。
4. Generator 在 trie constraint 下生成 SID candidates。
5. value head 或 discriminative multi-task head 预测 watch/order/GMV。
6. SFT/MTP 学历史行为，value-aware fine-tuning 对齐高价值 action，再用安全的 offline/simulator RL 做 exploration。
7. online 用 cache、asynchronous live encoder、partial run、small beam；保留 cascade fallback。

### 6.6 Reward

不要直接写 R = GMV。可说：

R = α·normalized_watch + β·order_value + γ·follow/interaction - λ1·quick_skip - λ2·complaint

并增加 hard constraints：

- user experience 指标不能显著下降；
- merchant ROI/库存/安全约束；
- creator exposure fairness/diversity；
- 对金额做 clipping/log transform，防止少量高价订单主导梯度。

权重由 offline sensitivity、Pareto analysis 和 online AB 逐步调，不宣称一次设定正确。

### 6.7 Evaluation

- offline：AUC/GAUC、LogLoss、HR/NDCG、calibration、coverage/diversity；
- counterfactual：IPS/DR/OPE，仅作风险筛选；
- online：分阶段 1%→5%→全量，guardrail + rollback；
- 观察短期 GMV，也看 retention、negative feedback、creator ecology；
- social/双边市场可能有 interference，必要时 cluster randomization。

### 8.2 传统推荐

#### Q3：AUC 相同的两个数据集混合后 AUC 一定相同吗？

不一定。每个子集 AUC 只约束子集内部 positive-negative pair 的排序；混合后会新增跨子集 pairs，且两个子集 score scale 可能不同，因此总体 AUC 可变。这也是 global AUC 可能受 group score scale 影响的例子。

#### Q4：为什么二分类常用 sigmoid + BCE，不用 MSE？

- Bernoulli likelihood 自然导出 BCE；
- sigmoid + BCE 对 logit 的梯度为 p-y，数值和优化更直接；
- MSE 不是分类概率的 proper likelihood choice，配 sigmoid 时容易在饱和区产生更弱梯度。

不要只答“因为 MSE 非凸”；神经网络整体本来就非凸。

#### Q5：为什么 L1 产生 sparsity？

在 0 处不可导，subgradient 是区间；proximal update 对 L1 对应 soft-thresholding，小权重会被直接压到 0。相比之下 L2 update 连续缩小参数，通常不直接变成 0。

#### Q6：预测 watch time 怎么做？

- 先定义 label：raw duration、capped duration、log(1+t)、watch ratio；
- 注意 duration bias：长视频天然有更大 watch time，上限也不同；
- 可做 regression、bucket classification/ordinal、survival/hazard；
- 与 CTR/valid view 联合 MTL；
- offline 看 MAE/Huber/NDCG/GAUC，online 看 total watch time 与 retention，同时守住 quick skip。

#### Q7：如何同时优化 CTR 和 watch time？

- MTL shared representation + task-specific heads；
- 对 label scale、frequency、gradient conflict 做动态 weighting；
- serving fusion 前做 calibration；
- 不只把两项硬加，先定义 product objective 和 guardrails；
- 用 AB test 找 Pareto frontier。

#### Q8：CVR delayed feedback 怎么办？

- 固定 attribution window 会把“尚未转化”的样本误标 negative；
- 可延迟训练、使用 delayed-feedback model/survival model、importance weighting；
- 区分 click→order 与 impression→order；
- 处理 refund/cancel；
- 用 event-time join，避免未来信息 leakage。

### 8.3 Generative Recommendation

#### Q9：Semantic ID 为什么比 raw item ID 好？

压缩 vocabulary、共享 coarse-to-fine structure、支持语义泛化和 long-tail/cold-start、自回归搜索更可行。缺点是 collision、codebook collapse、SID drift 和 invalid path，因此必须配合 quantization quality 与 constrained decoding。

#### Q10：怎么把 collaborative signal 放进 LLM？

可分三类：

1. embedding feature：把 collaborative embedding 投影到 LLM space；
2. tokenization：基于 collaborative + multimodal embedding 构造 Semantic ID；
3. joint training：next-item/contrastive/multi-task objective 与 language/content objective 联训。

关键不是把 item title 变成文字就结束；纯文本会丢掉 user-item interaction 中的 collaborative knowledge。

#### Q11：生成式模型如何保证不生成下架商品？

每个 request 基于当前 inventory、targeting、stock/budget 建合法 SID trie；decoder 每步 dynamic mask，只扩展合法 child。仍应有 final validation 和 cascade fallback。

#### Q12：为什么 beam search 不一定适合 reward-aligned recommendation？

beam search 最大化 model likelihood，不是 GMV/watch reward；high-value long-tail item 的早期 prefix 概率低时会被永久剪掉。candidate 还可能共享 prefix，造成 diversity 低和 GRPO advantage compression。

#### Q13：Generative Recommendation 真能替代 cascade 吗？

研究目标可以统一，但工业落地常是渐进式：先替换 retrieval/pre-ranking 或与 discriminative head hybrid；保留 constraint engine、fallback、AB rollout。是否完全替代取决于 latency、coverage、dynamic inventory 和 reliability。

### 8.4 RL in Recommendation

#### Q14：如何把推荐写成 MDP？

- state：user long/short history、context、当前 session、已展示 slate；
- action：single item、slate，或 SID token/path；
- reward：watch/order/GMV/negative feedback/long-term retention；
- transition：用户行为改变 history 与后续兴趣；
- policy：在合法 candidate space 上选择 item/slate。

若只优化单次 request 且不建模长期 transition，更接近 contextual bandit。

#### Q15：会不会直接用 GRPO 在线优化 GMV？

不会直接上线探索。先：

1. 用 logs/SFT 得到稳定 policy；
2. 建 simulator/reward model，并做 calibration；
3. 用 conservative constraints、KL、action mask；
4. offline OPE/回放筛选；
5. 小流量 AB，设置 watch/complaint/latency guardrails；
6. 保留即时 rollback。

还要注意 reward model exploitation 和未曝光 action 的 value overestimation。

#### Q16：推荐场景如何构造 GRPO group？

同一个 user context 生成 G 个合法 candidate item/SID path，用 calibrated reward/value 得到 group-relative advantage。问题是 candidate 相关、共享 SID prefix，标准全局 group normalization 可能压缩 sibling 的差异；可按 tree structure 做 Sibling-GRPO。

#### Q17：RL 相比 DPO 的价值？

DPO 对 pairwise preference 稳定、实现简单，不需要 online rollouts/reward model sampling；RL 能直接优化 non-differentiable scalar reward、主动 exploration，但更容易不稳定和 reward hacking，system cost 更高。常见路径是 SFT → DPO/value-aware FT → constrained RL。
